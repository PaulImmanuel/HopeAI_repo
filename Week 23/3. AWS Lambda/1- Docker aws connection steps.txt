Step 5 - Push to Amazon ECR (Important)
⚠️ If using newer Docker Desktop (v4.7x or later)

New Docker versions create an OCI Image Index, which AWS Lambda may reject. Instead of a normal push, build and push using Buildx with provenance disabled.

docker buildx build --platform linux/amd64 --provenance=false --push -t 838993198759.dkr.ecr.ap-south-1.amazonaws.com/websiteaichatbot:latest .

This produces a Lambda-compatible image.

The first push can take several minutes...Once the push finishes, we'll go to the AWS Console:

Amazon ECR
    ↓
Repositories
    ↓
websiteaichatbot
    ↓
Images

The image should appear as: Type - Image

Common Issues & Fixes
1. Unable to reach the server

Cause:

CORS is not configured correctly.

Fix:

Enable CORS in API Gateway.
Allow GET, POST, and OPTIONS.
Allow the correct origin.
2. 404 Not Found on OPTIONS /chat

Cause:

The browser's CORS preflight request isn't handled.

Fix:

Configure CORS properly in API Gateway so OPTIONS requests succeed.
3. Lambda changes don't appear

Fix:

Build and push the new Docker image.
Click Deploy new image in Lambda.
4. Wrong API Gateway URL

Symptoms:

API works in Lambda tests but not from the frontend.

Fix:

Use the current API Gateway Invoke URL in script.js, not an older API endpoint.
